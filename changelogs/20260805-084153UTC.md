# 2026-08-05 — Cleanup, dead code removal, and small fixes

## Config & error handling

- `DoryConfig` now uses `#[derive(Default)]` instead of a manual `impl Default`.
- `AkaError::InvalidService` now carries the list of valid options, so its message is accurate per call site.
- `Up`/`Down`/`Pull`/`Attach`/`Ip`/`Logs` now reject unrecognized service names with a real error instead of silently no-oping (`Attach`/`Ip`/`Logs` previously logged an error but still exited `0`).
- `DoryConfig.debug` is now actually respected: `debug: true` in config has the same effect as always passing `--verbose`. Loaded best-effort at startup so a broken config file can't block `aka config-file --force`'s recovery path.

## Dead code removed

- `resolver::linux::LinuxResolver::resolv_file` (redundant duplicate of the free function).
- `resolver::macos::MacosResolver` struct entirely (unused wrapper with no logic beyond the free functions it duplicated).
- `resolver::os::OsType::is_macos` / `is_linux` (codebase only ever dispatches via exhaustive `match`).
- `resolver::macos::system_resolv_file_contents`.
- `services::systemd::systemd_service_installed` / `systemd_service_enabled`.
- `services::proxy::ProxyService::start`, `build_run_command`, `shell_escape` (an entire alternate container-start implementation superseded by `ensure_running` → `DockerClient::ensure_container`).
- `docker::DockerClient::start_container` (superseded by `ensure_container`'s recreate-always design).

## Dead code wired in instead of deleted

- `resolver::has_our_nameserver` / `resolv_file`: now surfaced in `aka status` output.
- `aka status --verbose`: dumps raw resolver file contents (`/etc/resolv.conf` on Linux, each `/etc/resolver/<domain>` file on macOS).
- `docker::DockerClient::get_logs`: new `aka logs [proxy|dns]` subcommand, mirroring `attach`.
- `port_utils::PortProcess`'s `command`/`user`/`name` fields: the port-conflict warning log now lists which process/command/user is holding the port, not just a count.
- `macos::contents_has_our_nameserver`: `has_our_nameserver` now delegates to it per file instead of duplicating the same check logic inline.

## systemd race condition fix

- `set_systemd_service` no longer sleeps a fixed, guessed duration. It polls `systemd_service_running` until the service confirms it reached the desired state (or a timeout elapses), covering both the stop path (confirming port 53 is released) and the start path (confirming a restarted service is actually back up).
- `service_start_delay` config field is unchanged in name/type/format — old `.dory.yml`/`.aka.yml` files remain compatible — but now means "max seconds to wait" instead of "always sleep this long."
- Added the first test in `services/systemd.rs` (`services_that_block_dnsmasq`).

## rust-analyzer false positives

- Worked around a rust-analyzer bug (`ERROR inference diagnostic in desugared expr`, false `expected String, found ()` on functions whose entire body is a macro call) in `resolver/linux.rs` and `resolver/macos.rs` by binding `format!`/`vec!`/`.collect()` results to a local variable before returning.

## Clippy

- Collapsed several nested `if` blocks (`Up`/`Down`'s per-service blocks, `Restart`'s dnsmasq/proxy blocks) into single conditions using `&&` and let-chains, per `collapsible_if`/`collapsible_else_if`. `cargo clippy --all-targets` is now fully clean.

## `.gitignore`

- Added `.aka.yml`, `.DS_Store`, `.idea/`, `.vscode/`, `*.swp`, `*.swo`.

## README

- Documented `aka logs`, `aka status --verbose`, the `service_start_delay` and `debug` config options, and added the missing systemd sudo requirement to the troubleshooting section.
